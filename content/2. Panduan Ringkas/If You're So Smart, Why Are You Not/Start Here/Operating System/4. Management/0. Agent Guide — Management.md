## Purchase Orders

- **Filename:** `PO YYYY-MM-DD — Vendor.md`. **Frontmatter** (`type: purchase_order`): `po_id` (`PO-YYYY-MM-DD-vendor`), `date`, `vendor`, `total_rm`, `item_count`, tags `operating-system, purchase-order`.
- **Body:** items table `| Item | Qty | Unit (RM) | Total (RM) | Remark |` + TOTAL row; `→ Stock` deltas where given.
- **Link every product item to its note — and escape the pipe.** A table cell separator is `|`, so an aliased wikilink inside a table **must escape its alias pipe as `\|`**: write `[[Compound (spec) — vendor\|the vendor's listing name]]`. An unescaped `[[X | Y]]` in a table splits the link across two cells and silently breaks it (this happened on the heiltropfen Methylene Blue row). Keep the vendor's own listing name as the display text; the link target is the catalog note. If a PO name doesn't match a note, resolve it via `compound`/`aliases`, then add that listing name to the note's `aliases` (Catalog rule 8) so the next identical PO line resolves automatically.
- **Pre-link audit:** before considering a PO done, scan every item row — each product row should be a `[[…\|…]]` link; only shipping / voucher / discount / true-gap rows stay as plain text. Non-product cost rows (shipping, coupons, discounts) are **not** product links.
- **Cardinal rule: a purchase isn't done until stock reflects it.** After logging a PO, post its deltas to each product's `stock_on_hand`, bump `stock_as_of`, verify the PO's spec matches the product note (a buy can change the spec), and dedupe Stock↔Wishlist (checks 1, 3, 4). Flow: [[Stock Reconciliation Policy]].
- **Never delete a PO** — it's the audit trail. Source of truth for past spend alongside the Expenses Google Sheet ("Stock Management").

## The `_Ledger` — how the loop works

When the agent needs something only Nadeem can provide (physical stock count, a price, a decision), it **creates or updates a ledger file** stating exactly what's needed; Nadeem fills it in; the agent consumes it to move forward. Files are also where computed results are written back so they persist between sessions.

| File | Purpose |
|---|---|
| [[Stock Forecast — Intake Protocol]] | **SOP:** the intake questions to ask BEFORE any stock forecast (horizon, current cycle, test-ester status, PED calendar, unlogged buys, …). Defaults: horizon = 31 Dec next year |
| [[Stock Reconciliation Policy]] | **SOP:** PO → `stock_on_hand` posting rules |
| [[Bi-Weekly Review]] | **SOP/cadence:** the recurring review ritual |
| [[Schedule Audit]] | Audit of dosing-schedule assignments vs reality |
| [[Monthly Nut]] | The unified E+F+X monthly ledger (Goal 1) |
| [[Freedom Numbers]] | Emergency 6mo + Freedom 24mo targets (Goal 4; E+F only, ×1.06 inflation) |
| [[Stock & Restock Plan]] | What to buy, when, at what cost (Goal 2) |
| [[Price & Sourcing Optimization]] · [[International Vendor Price Sheet]] · [[Peptide Price Comparison]] · [[Cut Compound Price & Vendor Comparison]] | Price-watch / negotiation sheets (Goal 3) |
| [[Cut Campaign Stock & Cost]] · [[Beligas Order — 2026 Q3 Cut]] · [[Equicare Order — 2026]] | Campaign/order working files for specific buys |

## The six checks (summary — full text in [[0. Agent Operating Checklist]])

1. **POs → stock** — sweep for buys newer than `stock_as_of`, post deltas.
2. **Date + protocols → depletion** — project run-out; periodically ask Nadeem to eyeball real stock.
3. **Catalog ↔ PO consistency** — a buy can change the spec; fix the note.
4. **Stock ↔ Wishlist dedup** — bought → move to Stock, same id.
5. **Sources current** — lead time, fees, trust; order slow vendors first.
6. **Schema + Uses context** — correct dose/frequency/cycle-weeks; factor [[Training Rhythm]] (≈5.25 d/wk) and [[Pinning Schedule]].

**When:** forecast/what-to-buy request → all six + intake SOP. New PO logged → 1, 3, 4. Before ordering → 5, 6.

## Agent rules for this folder

1. Run the checklist before computing anything; run the intake SOP before any forecast — **ask first, then forecast**.
2. Leave a ledger trail: blocked on Nadeem? Create/update a ledger file with the exact ask. Computed something durable? Write it back to the relevant ledger file, don't leave it in chat only.
3. Keep prices synced: a price seen in a PO or vendor sheet that differs from the product note → update the note.
4. Dose/calendar numbers are **provisional until bloodwork confirms** — note it when costing PED forecasts.
5. Check [[0. Reconciliation — Gaps]] and [[QC & Gap Analysis]] before claiming completeness — known holes: uncatalogued buys, food/protein premium, insurance, some software.
