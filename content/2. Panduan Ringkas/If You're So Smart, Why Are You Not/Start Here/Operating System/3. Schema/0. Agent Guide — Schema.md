> [!abstract] **The qualitative→quantitative bridge.** Uses holds the theory of *how* things are used; this folder breaks that theory into numbers so it can be computed. Two things live here: the authoritative **field model** for every note type ([[Schema — Data Model]]) and the **dosing-frequency engine** (`Dosing Schedules/`) whose `days_per_week` factor drives every stock and cost forecast in the OS.

## Folder map

| Path | What lives there |
|---|---|
| `Schema — Data Model.md` | **Authoritative spec**: field-by-field model for Product, Dosing Schedule, Cycle, Source, Overhead note types + all Base views + the parked Postgres mapping. When unsure what a field means, read this. |
| `Dosing Schedules/` | Six dictionary notes (`type: dosing_schedule`), one per code |
| `Dosing Schedules/0. Dosing Information.base` | View over the six codes with their forecast factors |

## The dosing engine

| Code | Note | `interval_days` | `days_per_week` | `forecast_method` | Agent notes |
|---|---|---|---|---|---|
| ED | Every Day | 1 | 7 | frequency | |
| EOD | Every Other Day | 2 | 3.5 | frequency | Lasts 2× as long as ED — the canonical "a spreadsheet can't see this" case |
| TD | Training Days | — | 6 (frontmatter) | frequency | **Override:** real rhythm is 3-on-1-off ≈ **5.25 d/wk** ([[Training Rhythm]]). Use 5.25 for forecasts |
| ITD | Intense Training Days | — | 4 | frequency | Subset of training days |
| OCC | Occasionally | — | 3–5 (default 4) | manual | Ask if precision matters |
| CYC | Cycling | — | blank | cycle | **Cannot forecast standalone** — needs cycle context: `weekly mg × weeks_per_year` / cycle `items` + `cycle_weeks` |

## The formula chain (compute in this order)

```
effective_daily   = daily_dose × days_per_week / 7        # per-day burn in dose_unit
total_units_mg    = package_size × base_dose              # total mg per bottle
cost_per_mg       = cost_per_bottle / total_units_mg      # NOT cost_per_bottle/package_size (unit bug)
cost_per_day      = effective_daily × cost_per_mg
cost_per_month    = cost_per_day × 30.44
days_until_empty  = stock_on_hand / effective_daily       # stock must be in dose_unit (mg)
landed_cost       = cost_per_bottle + allocated_shipping + fees   # shipping model from Source note
```

Roll-up guards: only `count_in_total = true` AND `status = active`; exclude Peptides (INDEXA-funded).

> [!warning] Known quirks — check before trusting any output
> 1. **`stock_on_hand` units are inconsistent** across notes (some mg, some tabs/ml). Normalise/verify the unit per note before dividing.
> 2. **`cost_per_dose` as stored/derived (`cost_per_bottle / package_size`) is cost per tab/ml, not per mg dosed.** Use the `cost_per_mg × daily_dose` chain above.
> 3. **TD frontmatter says 6/7** but the standing rhythm is ≈5.25 — prefer the rhythm.

## Agent rules for this folder

1. Never compute burn without resolving the product's `dosing` code to its `days_per_week` here.
2. CYC and on-cycle items: resolve context in `1. Uses` (cycle `items`, `weeks_per_year`, [[Endocrine Design Rules]]) — annual burn = weekly amount × weeks-on, not ×52.
3. Consumables (syringes, swabs) follow [[Pinning Schedule]] (pins/week), not a dosing code.
4. This folder is a **dictionary — it changes rarely.** Don't edit schedule factors to make a forecast fit; if reality differs, the product's `dosing` field or the protocol is what's wrong.
5. Changing the field model? Update [[Schema — Data Model]] first, then the notes — the spec leads, the data follows.
